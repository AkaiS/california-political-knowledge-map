# Scraping Pipeline PRD

Status: ready-for-agent

## Problem Statement

Website layout changes frequently cause CSS-based scrapers to break or extract malformed text, leading to empty fields, boilerplate text (navigation links, ads, sidebars), or missing sections. Ingesting malformed text is highly problematic for GraphRAG entity extraction because it is expensive and pollutes the knowledge graph with dirty data.

Additionally, news sites publish many articles that are irrelevant to California political networks (e.g., sports, lifestyle, recipes, general national news). Crawling and running LLM extractions on these irrelevant articles is highly expensive and contaminates our knowledge base. 

As the number of tracked news publications grows, we need a robust method to:
1. Validate that scraped article content matches a heuristic baseline.
2. Store historic iterations of selectors since websites change over time.
3. Automatically generate and self-heal CSS selectors using LLMs when layout drift is detected.
4. Bootstrap selectors for new publications using sample articles.
5. Provide a human-in-the-loop validation step to approve new selectors before they are promoted and applied.
6. Manage all publication configurations dynamically in the database, avoiding static files and enabling easy registration of new publications at runtime.
7. Filter out non-political articles during URL discovery using local, fast, keyword-based keyword relevancy matching.

## Solution

We will build an advanced scraping pipeline with self-healing capabilities:
- **Registry**: A database table `publications` that specifies publication details, crawl policies, and discovery methods, but does *not* contain HTML selectors.
- **Selector Store**: Mapped in SQLite (`publication_selectors`), storing versioned CSS selectors with time-range validity windows (`valid_from` to `valid_to`).
- **Relevance Filter**: Constructs a `Relevance Document` for each page (combining title, meta description, keywords, and sections) and runs BM25 query scoring against it using a single, robust, global California politics query. Pages below a configurable threshold are discarded before main body parsing, validation, or database storage.
- **Article Validator**: Compares the CSS-extracted article against a heuristic extraction baseline generated by `newspaper4k`. It enforces strict title, author, and date validation and compares the article body lengths.
- **Raw HTML Store**: Stores the raw HTML of articles that fail validation as a `VALIDATION_FAILED` status in SQLite.
- **Selector Healing Pipeline**: An asynchronous LLM-driven process (Generator/Critic loop) that analyzes validation failures to generate new selectors.
- **Publication Bootstrapper**: An LLM-driven process to discover selectors for a new publication.
- **CLI Management**:
  - `ca-map register-publication` - CLI command to register a new publication in the database and trigger the bootstrapper.
  - `ca-map update-sources` - Incremental crawl that skips existing URLs, filters relevance, and flags validation failures.
  - `ca-map scrape-archive` - Archive crawl that respects the `DiscoveryState`, relevance filtering, and configurable cutoff.
  - `ca-map review-selectors` - CLI utility for developers to view LLM-generated selector candidates, preview extraction outputs, and approve/promote them to active status.

## User Stories

1. As a developer, I want to define publications in a SQLite database table instead of a static configuration file, so that publication configurations are dynamic and can be queried and modified at runtime.
2. As a developer, I want to use `ca-map register-publication` to register a new publication in the database, so that adding new sources is fully automated.
3. As the scraper, I want to query the SQLite `Selector Store` using the article's date, so that I can use the version of CSS selectors that was active when the article was published.
4. As the scraping pipeline, I want to run `newspaper4k` on scraped pages to get a heuristic extraction baseline, so that I can validate the quality of my CSS-extracted data.
5. As the validation step, I want to fail validation if the CSS-extracted title, author, or date does not match the baseline, or if the body length differs by a large margin, so that malformed data does not enter the ingestion pipeline.
6. As the scraper, I want to save the raw HTML of any validation-failed article in the database and set its status to `VALIDATION_FAILED`, so that we have the exact page state for debugging and self-healing.
7. As a developer, I want to run an asynchronous self-healing loop that reads `VALIDATION_FAILED` articles and raw HTML to generate new selector candidates using a Generator/Critic LLM team.
8. As a developer, I want to bootstrap a new Publication by pointing the system to a few sample article URLs, which runs the LLM selector generator to produce the initial selectors.
9. As a developer, I want to run `ca-map review-selectors` to inspect proposed selectors, view a visual diff/preview of the extracted content against the raw page, and approve them before they are written as active `Selector Versions`.
10. As a developer, I want to automatically re-parse and validate stored raw HTML files for `VALIDATION_FAILED` articles once their publication's selectors have been updated, so that they are promoted to `UNPROCESSED` for GraphRAG ingestion.
11. As a developer, I want the scraper to compute a BM25 relevance score for each discovered URL using a Relevance Document and a single, global California politics query, so that we filter out irrelevant articles consistently across all publications.

## Implementation Decisions

- **Registry & Selector Store SQLite Schema**:
  ```sql
  CREATE TABLE IF NOT EXISTS publications (
      id TEXT PRIMARY KEY,               -- e.g., 'calmatters'
      name TEXT NOT NULL,                -- e.g., 'CalMatters'
      base_url TEXT NOT NULL,            -- e.g., 'https://calmatters.org'
      crawl_delay REAL DEFAULT 2.0,
      max_concurrency INTEGER DEFAULT 2,
      use_robots_txt BOOLEAN DEFAULT 1,
      discovery_strategy TEXT NOT NULL,  -- e.g., 'paginated_listing' or 'sitemap'
      discovery_config_json TEXT,        -- JSON containing page pattern, start page, etc.
      relevance_threshold REAL DEFAULT 0.5,
      archive_cutoff_years INTEGER DEFAULT 5,
      created_at DATETIME DEFAULT CURRENT_TIMESTAMP
  );

  CREATE TABLE IF NOT EXISTS publication_selectors (
      id INTEGER PRIMARY KEY AUTOINCREMENT,
      publication_id TEXT NOT NULL,
      selectors_json TEXT NOT NULL,      -- JSON containing article and listing selectors
      valid_from DATETIME NOT NULL,
      valid_to DATETIME,                 -- Nullable if currently active
      created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
      FOREIGN KEY(publication_id) REFERENCES publications(id) ON DELETE CASCADE
  );
  ```
- **Raw HTML Store SQLite Schema**:
  ```sql
  CREATE TABLE IF NOT EXISTS scraped_html_cache (
      url TEXT PRIMARY KEY,
      raw_html TEXT NOT NULL,
      scraped_at DATETIME DEFAULT CURRENT_TIMESTAMP
  );
  ```
- **Global Relevance Query**:
  Configured as a global constant `POLITICAL_RELEVANCE_QUERY` in `config.py`:
  `california sacramento governor newsom assembly senate legislature legislation lobbyist lobbying ballot measure proposition prop bill senator assemblymember political election PAC campaign donor`
- **Relevance Document Construction**:
  For each discovered article page during discovery, the crawler extracts:
  - Title (`og:title` or `<title>`)
  - Description (`og:description` or `<meta name="description">`)
  - Keywords (`<meta name="keywords">` or `<meta name="news_keywords">`)
  - Article Section/Tags (`og:article:tag` or `<meta property="article:section">`)
  These are concatenated into a single string. A BM25 tokenizer processes this string (lowercasing, stemming, stop-word removal) and calculates the similarity score against the global query. If the score is below the publication's `relevance_threshold`, the article URL is skipped.
- **Validation Rules**:
  - **Title**: Case-insensitive string similarity (e.g., edit distance ratio >= 0.90) between CSS-extracted and `newspaper4k` baseline.
  - **Author**: CSS-extracted must exist and match baseline if baseline successfully identifies an author.
  - **Date**: Extracted publish date must resolve to the same calendar day as the baseline.
  - **Body Length**: The ratio of the length of the CSS-extracted content to the `newspaper4k` baseline text must fall within `[0.85, 1.15]` (configurable percentage).
- **Generator/Critic Agent Flow**:
  - **Generator Agent**: Receives raw HTML, target baseline text, and metadata. Outputs CSS selectors for listing and body.
  - **Critic Agent**: Receives the raw HTML and the content extracted using the Generator's proposed selectors. Validates presence, cleanliness, and length ratio. Outputs approval or specific feedback (e.g., "social share buttons found under selector X").
- **Human Approval Seam**: Proposed selectors are saved with a status of `pending_approval` or written to a `.scratch/proposed_selectors.json` report. The CLI command `ca-map review-selectors` displays the preview and prompts for a confirmation `y/n` input to promote it.

## Testing Decisions

- **Good Test Criteria**: Tests must verify lookup of time-range selectors from the DB, the logic of the `Article Validator` comparison rules, the state changes from `VALIDATION_FAILED` to `UNPROCESSED`, BM25 tokenization and thresholding, and selector generator mock runs. 
- **Modules to Test**:
  - Selector Store queries (time range boundaries).
  - BM25 Relevance filter (scoring matches, threshold validation, and skipping).
  - Article Validator (different types of mismatches, matching body lengths).
  - CLI parser subcommand additions (`register-publication`, `review-selectors`, `scrape-archive`, `update-sources`).
  - Asynchronous healing coordinator.
- **Prior Art**: We will mock the LLM calls for Generator/Critic and mock `newspaper4k` outputs to test the self-healing and validator modules in isolation.

## Out of Scope

- Automatic correction of sitemap formats or RSS layout changes.
- Human-in-the-loop UI (the terminal CLI is sufficient for the approval step).
- Healing of third-party APIs (strictly covers news publication HTML websites).

## Further Notes

- Once a Selector Version is approved and activated, the system can sweep all `VALIDATION_FAILED` articles from the corresponding publication, re-run the CSS selector parsing on their saved raw HTML, validate them, and mark them `UNPROCESSED` for the ingestion pipeline.
