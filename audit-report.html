Agent-Traversability Audit — audit-project worktree

Note added after the fact. This audit quotes the code as it stood, and is left unedited. Two things it names have since been renamed: evaluation/gold_set.py is now evaluation/data_set.py, and "Gold Set" is now "Evaluation Data Set". Only evals/gold/relevance.yaml was ever gold — a person labeled it. The coreference, extraction, Policy Area Classification and Topic Assignment sets were labeled by a model against a written guideline, are Silver Sets, and moved to evals/silver/. The line counts under evals/gold/ below cover all five.

Why agents get lost in this codebase: stale language polluting context, unenforced rules that keep getting dropped (Logfire in evals, reuse-before-build), and no progressive disclosure (one 66-term CONTEXT.md, ~2,200 lines of preload before code). Findings below are cited file:line and paired with 2025–2026 industry patterns.

0 · Executive summary

The codebase is well-tested and well-intentioned, but it optimizes for human archaeology over agent traversal. Every agent pays the same three taxes:

  1. Contradictory preload. README.md (event-driven GraphRAG, Tenacity, Claude/OpenAI fallback, CI/CD evals) contradicts CONTEXT.md + src/ (synchronous Story Pipeline, llama.cpp + OpenRouter, no queue, no CI). AGENTS.md:11 says only Neo4j; code + CONTEXT.md say SQLite + Neo4j. The ghost term Influence Graph Playground → playground.py names a file that does not exist.
  2. Decisions live in the wrong layer. AGENTS.md:44 forbids architecture decisions in code, yet 5 eval modules cite ADR 0017 in docstrings, sqlite_db.py carries an undated legacy_column_reader shim (15 call sites), and utils/models.py:543 monkeypatches a private pydantic-ai name — the exact failure CONTEXT.md:286-289 warns will “break silently on upgrade.” Agents cannot tell live constraints from history.
  3. No disclosure ladder. ~2,229 lines (CONTEXT.md 289 + docs/ 903 + ontologies 362 + work/README+roadmap+inbox 675) load before any code. 8 superseded ADRs (0005–0012) + work/archive/superseded-by-adr-0017/ (~60 dead issue files) + a 233-line work/README.md reconciliation log force agents to read deleted systems to understand the live one.

Highest-leverage fixes (details in §7–8): shrink root AGENTS.md to a router with runnable uv commands; split the 66-term CONTEXT.md per bounded context behind a CONTEXT-MAP.md; convert ADRs to agent-checkable guardrails (verify: grep/pytest); lint the glossary (Article/Story/document/chunk); add the two missing enforced rules (Logfire in evals, reuse-before-build); archive or quarantine dead docs.

2 · Inconsistent language polluting context HIGH

L-1 · README vision vs shipped system. README.md:1-2 “enterprise-grade, event-driven data pipeline … campaign finance data, and legislative records”; README.md:5,9 “queue-based … exponential backoff (Tenacity), fallback multi-provider routing (Claude/OpenAI) … CI/CD evals/ pipeline.” Reality: no event bus/queue in src/; core/pipeline.py:120 def run(self, article: SourceArticle, dry_run=False) is the synchronous coordinator CONTEXT.md:170-172 defines; providers are local llama.cpp GGUF + OpenRouter (docs/model-deployments.md:5-9, utils/models.py:22-28); no CI config; pipeline ingests SourceArticle → coref → chunk → embed → extract → SQLite/Neo4j. Effect: agents plan queue/retry/Claude work that does not exist.
README: “resilient, queue-based data pipeline that isolates raw data scraping from LLM processing” — no queue exists; Story Pipeline is synchronous.
L-2 · Which database? AGENTS.md:11 lists only DB: neo4j (Graph Database). CONTEXT.md names SQLite 3× (Discovery State :20, selector_proposals :80, stories :120) and Neo4j 2×. Code has both: adapters/sqlite_db.py:15 DEFAULT_DB_PATH="document_store.db" (1,726 lines) + adapters/neo4j_db.py. README.md:29 says setup symlinks document_store.db — absent in this snapshot. Agents must discover the dual-store topology by reading code, not entry docs.
L-3 · Article / Story / Source Article / document collapse. Glossary (CONTEXT.md:119-129): Story = extracted record, stories table, VALIDATED ⟺ row exists (Avoid: Article, document); Source Article = ingestion input (Avoid: document, post); Article Chunk = segment. Violations:
  • schemas/pipeline.py:7 class ArticleStatus tracks a Story (schemas/stories.py:17-18 status: ArticleStatus); sqlite_db.py:19 STORY_STATUS_CHECK = sql_check_values(ArticleStatus) mixes both in one line; sqlite_db.py:41 class ArticleMetadataUpdateResult + :385 _story_columns(story: Story) — three names, one row.
  • schemas/pipeline.py:15 class StoryLink (“hyperlink extracted from an article body”) is used on both SourceArticle.links and Story.links.
  • SourceArticle (schemas/pipeline.py:30) and Story (schemas/stories.py:6) share title/author/date/content/links shapes across two modules; neo4j_db.py:205 ingest_article(article: SourceArticle) vs sqlite_db.py:407 save_story(story: Story) — same lifecycle, different verbs.
  • Banned document appears in evaluation/gold_set.py:91 document = yaml.safe_load(…), report_file.py:78 document = {…}, adapters/embedding.py:98,102,115 embed_documents, resources/extraction_prompt.txt:2 “article or document”, ontology/render.py:33 lowercase “article” for Source Article.
  • ArticleStatus / ArticleSelectors / ArticleChunk / SourceArticle / Story — five prefixes for one lifecycle; Article Selector and Article Validator are glossary-compliant but collide with the banned bare Article.
L-4 · One claim-key rule, three sources of truth. ontology.md:93-113 (authored, Bill id + ADR 0014 note) → news-ontology.md:87-99 (generated divergence table: name/session_verified/needs_review/transaction_id) → CONTEXT.md:190-212 (News Ontology, Shortcut Rule vs Divergence, Bill Designation, Bill Session Resolution, Legislative Event Date in prose). Agent must triangulate all three for one edge-identity decision. The generated-file banner (news-ontology.md:1 “do not edit”) is the only clear ownership signal.
L-5 · Ghost term + missing ADR number. CONTEXT.md:140-142 “Influence Graph Playground … implemented in playground.py” — glob **/playground.py is empty. docs/adr/ jumps 0017 → 0019; 0017’s text explains 0018 lived on an unported branch. Both are small, but each costs an agent a fruitless search.
L-6 · Blank tech stack + broken absolute links. AGENTS.md:4-13 leaves 4 of 9 fields blank (LLM Providers, Orchestration, LLM Tooling, CI/CD) while pyproject.toml:7-23 (fastapi, crawl4ai, chonkie, logfire, structlog, pydantic-evals…) and docs/model-deployments.md + CONTEXT.md:249-267 (local llama.cpp vs OpenRouter) carry the real answers. 3 · Architecture decisions living in code HIGH

House rule AGENTS.md:42-44: “Comments exist to describe the problem the code is solving… The place to document architectural decisions is never directly in the code.” The repo violates its own rule systematically:

S-1 · ADR pointers in every eval module. evaluation/__init__.py:1, gold_set.py:4, engine.py:4, report_file.py:4, cli/evaluate.py:4 — all cite “see ADR 0017” in docstrings. (No TODO/FIXME/HACK at all — the issue is not litter, it is duplicated authority: the decision now lives in both ADR and import path.)
“Evaluation over Gold Sets authored as files, versioned by git (ADR 0017).” — evaluation/__init__.py:1
S-2 · Undated legacy shims. adapters/sqlite_db.py:48,56,59 + 15 call sites legacy_column_reader / legacy_value for pre-migration schemas; adapters/embedding.py:39 “Keep the legacy embedding variable as a compatibility read”; adapters/coreference.py:911 “legacy DLQ issue field”; evaluation/tasks/relevance.py:67, coreference.py:147 “Turn a legacy model argument into…”; utils/models.py:696 “legacy caller”. No dates, no removal criteria, no ADR links — agents treat them as live API.
S-3 · Private-name monkeypatch in the hot path. utils/models.py:543-557 patches OpenAIChatModel._MapModelResponseContext._into_message_param (null→“”) because llama.cpp rejects null content on retry turns. CONTEXT.md:271-289 embeds the same 19-line operational constraint and warns it “will break silently on a pydantic-ai upgrade … Check this first when a previously working agent starts failing intermittently after a dependency bump. Verified against pydantic-ai 2.0.0.” Correct diagnosis, wrong layer: a load-bearing version pin + upgrade tripwire living half in prose, half in code.
S-4 · Workarounds without expiry. core/discovery.py:304-305 BeautifulSoup href-to-text fallback “where Crawl4AI does not capture anchor text inside nested elements”; utils/models.py:710-725,832-833,906-907 llama-server parser quirks, OpenAI retry-counting notes. Some are excellent problem-comments buried in a 1,456-line file where agents cannot separate signal from restatement (see §4).
S-5 · God-modules + a lazy-import smell. sqlite_db.py 1,726 + models.py 1,456 lines; core/validation.py:10-43 fans into config/schemas/adapters/core/console/urls; core/healing_runner.py:8 imports cli.main.setup_logging (CLI→core cycle risk); core/pipeline.py:93-95 lazy-imports CoreferenceResolutionError, ExtractionError inside a method to dodge a cycle. Agents editing these files inherit the tangle.

4 · Rules that keep getting dropped HIGH

R-1 · “No Logfire in evals” — by omission. grep logfire|setup_telemetry|instrument in evaluation/ + cli/evaluate.py → 0 hits. Telemetry exists only on the pipeline path: utils/telemetry.py:25-61 setup_telemetry() (logfire.configure + instrument_pydantic_ai/httpx/system-metrics), called from cli/main.py:28,153-195, core/healing_runner.py:24-26, utils/agents.py:13, utils/models.py:513; spans in core/healing.py:351 heal_selectors, core/discovery.py:509 scrape_publication, core/validation.py:651. evaluation/engine.py:60-142 run_gold_set (via Dataset.evaluate_sync), both task modules, provenance.py, and cli/evaluate.py never call it; pyproject.toml:38-39 silences LogfireNotConfiguredWarning. Request Provenance is file-recorded (report_file.py:78-89), never traced — so cost/route/attempt evidence the model-deployments doc teaches agents to read has no live counterpart. If the rule is “evals are observed,” it is neither written nor enforced.
R-2 · Reuse-before-build is stated, not enforced. AGENTS.md:18 “avoid building anything already solved by libraries… measure twice, YAGNI.” Counter-examples agents will copy:
  • Retry: correct base (utils/models.py:29-30 AsyncTenacityTransport, RetryConfig) + ~600 lines custom: _RequestRetryState:51, tracking transports :444-493, OpenRouter Admission Gate + probe + adaptive limit :752-984, wait hooks :996-1202, build_retrying_client:600-631. History shows why: work/projects/coreference-retry-layering/ exists because pipeline.py used to retry with _execute_with_retry + classify_api_error + time.sleep (since removed).
  • Chunking/sentences: utils/chunking.py:2-54 wraps chonkie.RecursiveChunker + OverlapRefinery + custom word-boundary snap and ArticleChunk mapping; utils/sentences.py:1-130 wraps chonkie.SentenceChunker(chunk_size=1) with custom NumberedSentence, min-length fold/merge, 5 invariant checks. Justified tiling guarantees — but 180+ lines agents must re-learn per edit.
  • Dates/strings: core/validation.py:73-78 hand-rolled Damerau-Levenshtein + :102-184 unescape/author-regex/date-format ladder, despite a python-dateutil dependency sitting unused in pyproject.toml:19.
  • Classifier boundary: classifier/src/classifier/trainer.py:1-116 hand-rolls sqlite→LogisticRegression→JSON weights instead of going through the pydantic-evals task or package boundary.
R-3 · Comment rule is unenforced — restatement dominates. AGENTS.md:43 “Comments describe the problem being solved.” Sample: utils/chunking.py:33,39,42,45,56 (“Initialize recursive chunker” above the constructor, “Run chunker” above the call… — 5 in one function); sqlite_db.py:84,102,227,343,356,365 (“Create X table” above each CREATE TABLE); sqlite_db.py:625,664 duplicate “Check if the publication ID exists”; core/discovery.py:43,46,74,85 numbered outlines mirroring if order; core/validation.py:136-184,340-455 (“Split on commas”, “Try ISO 8601”…). Good problem-comments exist (schemas/chunking.py:13-17 overlap-consumption contract, neo4j_db.py:64-74 Claim-Key/Chunk rule, sentences.py:25-28 raise-not-assert for -O, sqlite_db.py:1251-1252 IS NOT vs != NULL semantics) but are indistinguishable from noise without reading whole files.
R-4 · YAML handling is fine — keep as positive example. evaluation/gold_set.py:91-95 yaml.safe_load → model.model_validate + cli/evaluate.py:145 yaml.safe_dump is a thin compliant wrapper. Cite it when writing the reuse rule so agents see the pattern, not just the prohibition.
