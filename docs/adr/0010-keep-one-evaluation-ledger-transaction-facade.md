# Keep one Evaluation Ledger transaction façade

Superseded by ADR 0017. Its use of "Gold Set" is retired too: four of the five sets were model-labeled and are now Silver Sets under `evals/silver/` — see the amendment to ADR 0017. The Evaluation Ledger and every mechanism this decision specifies for persisting, versioning, or finalizing evaluation records are removed; Gold Sets are YAML files and run reports are JSON files, both versioned by git.

The SQLite Evaluation Ledger remains one thin persistence façade and transaction owner while delegating to three focused internal components sharing the same connection: an Authored Definition Catalog, an Evaluation Execution Store, and an Evaluation Artifact Catalog. Schema installation is a separate technical component. The evaluation engine depends on the single Evaluation Ledger boundary, and operations spanning internal components are coordinated by the façade so run creation, case checkpoints, report checkpoints, and guarded completion remain atomic. We chose this structure over independently connected repositories because cleaner files are not worth weakening cross-table invariants or leaking transaction orchestration into the evaluation engine. There is no production evaluation ledger to preserve, so this change installs one clean schema and provides no migration or backwards-compatibility shim for the prototype layout.
