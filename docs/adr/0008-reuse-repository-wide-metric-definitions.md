# Reuse repository-wide Metric Definitions

Each Evaluation Metric Definition is an immutable repository-wide authored definition with identity `(namespaced name, evaluator revision)` and a canonical content hash. Authored Evaluation Suites remain self-contained by embedding the exact Metric Definitions they declare, and Configured Evaluators reference those declarations; when a Suite is imported, the ledger normalizes each definition into one canonical metric record, stores the Suite-to-metric relationships, and rejects conflicting content for an existing identity. A type-agnostic evaluator may reuse one Metric Definition across different Evaluation Task Contracts when the observation value schema, semantic meaning, and comparison operation are unchanged—the Metric Definition validates the observation value, while task-type compatibility remains the responsibility of the Gold Set, Suite, and Task Binding. The negligible storage saved by Suite-local definitions is not worth allowing apparently comparable observations to carry different meanings, and a semantic metric change requires both a new Metric Definition revision and a new revision of every Suite that adopts it.
