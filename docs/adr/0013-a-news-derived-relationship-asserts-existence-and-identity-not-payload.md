# A news-derived relationship asserts existence and identity, not payload

A relationship extracted from a Source Article asserts that a claim exists and what identifies it, and nothing else. Its declared properties, and only those, are its Claim Key; there is no second table of identifying properties beside the declaration. The rule that fixes the declaration is therefore the rule that fixes identity: if two different values mean two different claims, the property is declared and is identifying; if they do not, the property does not belong on the edge at all, and what the article said about it stays in the Article Chunk the edge points back to.

An edge carries exactly four things: its Claim Key, in the pattern the merge is keyed on; the list of Article Chunks that assert the claim; `skips` where the edge is a Shortcut Rule; and `needs_review` where an article asserted the claim without a value the key depends on. There is no trailing property assignment, so an edge holds no free payload a later ingestion could silently overwrite. Two articles asserting the same relationship at equal Claim Key values accumulate onto one edge; at differing values they produce two edges, and the disagreement between the sources stays visible rather than being resolved by ingestion order. Property normalization survives, scoped to Claim Key properties and running in one place, because making two articles' claims comparable is now its only job.

Nuance is not lost, it is relocated. Every extracted entity carries `MENTIONED_IN` to its Article Chunk and every extractor-produced relationship carries its chunk list, so the detail dropped from the edge remains retrievable through the chunk. That structural traceability is what makes an empty edge acceptable, and it is the reason no separate provenance property is stamped.

## Considered options

Keeping a separate identifying-property table alongside the declared properties allows an edge to hold descriptive payload, but two tables that can disagree means edge identity has two authorities. Merging on endpoints alone and assigning properties unconditionally — what the write path did before this decision — collapses two genuinely different claims into one edge holding whichever was ingested last, with no record that they differed. Recording every article's phrasing on the edge as a list would preserve the detail, but the chunk already preserves it, and an edge that accumulates prose stops being a claim and becomes a second, weaker document store.

## Consequences

**Node primary key minting is an ontology-level contract.** If an edge's meaning is carried by identity rather than payload, then identity has to be reproducible outside the news write path. `src/knowledge_map/ontology/keys.py` exports the general derived key and the Bill key, and both existing Bill key call sites import it. This is not speculative generality: a key two ingesters must agree on byte-for-byte is the difference between a later legislative ingester enriching a news-derived `Bill` and creating a second one beside it.

**A `LegislativeEvent` keeps a name-derived key, and its date is recorded but never keyed.** The event records the date the article stated, or the article's publication date where it stated none, with the source flagged the way Bill Session Resolution flags verified against inferred. The `Bill` precedent does not transfer: bill numbers collide across sessions by design and the failure is conflation, which nothing downstream can undo, whereas a Legislative Event's failure is fragmentation, which a later join on date and bill can repair. Keying a guessed date would trade the recoverable failure for the unrecoverable one, and keying the date only when verified would give Legislative Events two identity shapes, when a later correct-date ingest can find every node it must fix only if there is one shape to look for.

**The vote relationships declare no properties.** `sequence_number` describes the event's position in a bill's lifecycle rather than one legislator's claim, so it sits on `LegislativeEvent`; `VOTED_AYE`, `VOTED_NO`, and `ABSTAINED` are left with an empty Claim Key. A news-derived vote edge and a later legislative-derived one therefore merge instead of duplicating, and the News Ontology declares the Divergence: a news-derived vote edge carries no roll-call position and no event discrimination.

**`FUNDED` is keyed on the amount and the date, not the disclosure id.** News relationship properties are inherited from the primary ontology so the two tables cannot drift, but inheritance alone over-reaches: `transaction_id` is an FPPC filing id, and a property prose never carries cannot differ between two articles, so it separates no two claims and belongs in no Claim Key. Inheriting it regardless stamped `needs_review` on every news funding edge, which left the flag unable to discriminate the case it exists for — an article that named a funder and a campaign but no figure. The News Ontology therefore declares it a Divergence and subtracts it from the inherited properties, through the same one table and one subtraction that node properties go through — a relationship divergence is not a different kind of thing for having a different subject. The extraction prompt is unchanged: it states how a value is written, not which values are owed, and a form that appeared and disappeared with ontology metadata would only be a moving target for the model. The id is the handle a later reconciliation against the disclosure record joins on and then stamps, which is the same shape as a `LegislativeEvent` carrying a date it does not key.

Entity Resolution is unchanged and unsolved. Name-derived keys still leave name variants as separate nodes, and a Legislative Event still fragments across articles that describe it differently.
