# Resolve case evaluation requirements before execution

The aggregate-report persistence portion of this decision is superseded by ADR 0011; Evaluation Reports are now derived from Frozen Aggregate Manifests over terminal checkpoints.

Evaluation Cases declare stable semantic Evaluation Requirements while Evaluation Suites own the Configured Evaluators, rubrics, metrics, and bindings that satisfy them, keeping case intent independent from evaluation mechanism. Before execution, one shared engine resolves suite-wide and requirement-selected evaluators into a deduplicated Resolved Evaluation Plan, persists its canonical JSON atomically with the manifest and pending results, and builds one bounded-concurrency Pydantic Evals Dataset for either in-memory or durable execution. Durable execution uses persistence-free, runner-owned lifecycle hooks to checkpoint cases, freezes the aggregate report input as a content-addressed Evaluation Artifact, and checkpoints report evaluators separately; interrupted case execution requires a distinct linked run, while an explicit idempotent Evaluation Finalization operation resumes missing report work on the same run under an execution lease. Finalization may request completion, but the ledger authorizes the transition transactionally only after every planned case and evaluator application has terminal evidence and the aggregate report is frozen; task failures, evaluator failures, missing metrics, and release-gate outcomes remain independent from workflow completion.
