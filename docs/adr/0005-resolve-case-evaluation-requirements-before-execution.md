# Resolve case evaluation requirements before execution

Evaluation Cases declare stable semantic Evaluation Requirements while Evaluation Suites own the Configured Evaluators, rubrics, metrics, and bindings that satisfy them, keeping case intent independent from evaluation mechanism. Before execution, one shared engine resolves suite-wide and requirement-selected evaluators into a deduplicated Resolved Evaluation Plan, persists its canonical JSON atomically with the manifest and pending results, and builds one bounded-concurrency Pydantic Evals Dataset for either in-memory or durable execution. Durable execution uses persistence-free, runner-owned lifecycle hooks to checkpoint cases, freezes the aggregate report input as a content-addressed Evaluation Artifact, and checkpoints report evaluators separately; interrupted case execution requires a distinct linked run, while an explicit idempotent Evaluation Finalization operation resumes missing report work on the same run under an execution lease.
