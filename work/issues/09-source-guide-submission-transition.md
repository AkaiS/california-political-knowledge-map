## Agent brief

**Category:** enhancement
**Summary:** After a question is confirmed saved, reset the input and take the
reader into a view of that question's search.

**Current behavior:**
The question form stays visible with its submitted text. The running guide
appears below the saved-guide list, leaving the reader in the ask-question view.
New question already clears the input, and Edit question fills it from a guide.

**Desired behavior:**
After confirmed submission, clear the question input and leave the question-entry
view. Bring the submitted guide's search view into view, including the complete
question, current status, and Cancel while its attempt is running. Keep New
question, Edit question, and saved-guide navigation available. If the response
already contains a terminal outcome, display that outcome without a false
searching state. A failed or uncertain submission retains the draft and tells
the reader to check saved guides before trying again.

**Key interfaces:**
- `POST /api/questions` returns a saved guide identity and current attempt.
- `SavedSourceGuide.question`, `latest_attempt`, and `guide_id` identify the
  submitted question and its running or terminal outcome.
- The reader's submission, New question, Edit question, and saved-guide
  selection interactions own input visibility, focus, and navigation.
- Existing application-owned execution and attempt cancellation remain the
  authority for work continuing independently of the displayed view.

**Acceptance criteria:**
- [ ] Confirmed submission clears the input and leaves the entry form out of
      the displayed search view. The saved question remains complete and visible.
- [ ] The selected guide is brought into view on desktop and mobile even with
      a long saved-guide list. This movement occurs for the explicit submission,
      not subsequent background polling.
- [ ] Running work shows search status and a Cancel control for that attempt.
      An already terminal response immediately shows its actual outcome.
- [ ] New question restores a visible, focused, empty input. Edit question
      restores a visible, focused input containing the selected guide's complete
      question and continues to create a new guide when submitted.
- [ ] Saved guides remain reachable from the search view. Navigation, starting
      another question, and leaving the page do not cancel independent work.
- [ ] Unconfirmed submission preserves the draft and the instruction to check
      saved guides before another submission. The UI does not automatically retry.
- [ ] A late submission or saved-guide response cannot overwrite a newer draft,
      switch a newer selection, or hide the entry form after New question/Edit.
- [ ] Background status refreshes preserve the reader's scroll and focus.
- [ ] Existing explicit Update/Retry and Cancel semantics, reading directions,
      ordinary article links, highlights, and disclosures remain available.

**Out of scope:**
- Redesigning saved-guide layout, contrast sections, or article-section matching.
- Query rewriting, approval steps, implicit conversational context, or new APIs.
- Retrieval, prompt, execution ownership, and storage changes.

## Validation

Exercise confirmed running and terminal responses, unconfirmed submission,
