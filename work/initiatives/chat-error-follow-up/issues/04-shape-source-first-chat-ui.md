# Shape a source-first Chat Session interface

Labels: enhancement, needs-info
Parent: [Chat Session error follow-up](../MAP.md)

## Outcome

Produce a bounded UI PRD and implementation issues that make relevant Source
Articles and reported disagreements easy to consult. Source links and relevance
notes should lead; original passages and Search details remain inspectable.

## Triage Notes

**What we've established so far:**

- The maintainer expects presentation and interaction work to require UI changes.
- `render_answer` currently emits every stored Article Chunk with its source and
  emits disagreement notes after those passages. Code inspection confirms the
  mechanism behind `chunks-as-output`; the desired visual design is not settled.
- `RetrievalAnswer` already supplies source citations, relevance notes,
  disagreements, evidence passages, and coverage/failure disclosures.
- Local Retrieval Chat already has loopback security, isolated one-question
  sessions, approval/correction flows, and expandable Search details. Those are
  existing behavior to account for, not features to rebuild by default.
- No source-first UI redesign was found in existing planned work. A narrow
  renderer improvement may achieve part of the goal; no framework is selected.

**What we still need from the maintainer:**

- Is the first deliverable a source-first answer view inside the current shell,
  or a replacement interface covering preparation, approval, and answers?
- Should disagreements precede the source list or appear with the affected
  sources, and how should supporting passages be opened?
- Should user approval remain if the original-question baseline removes
  rewriting? Coordinate this with that issue rather than decide it here.

## Completion criteria for shaping

- [ ] Record the initial interaction scope and the existing behavior it relies on.
- [ ] Cover successful, partial, empty, and failed-search answer states using
      controlled examples and the accepted coverage output distinctions.
- [ ] Make source links and relevance visible without reading all stored passages.
- [ ] Give disagreement notes a prominent, source-linked place without adjudicating
      reported positions.
- [ ] Specify optional original-passage and Search details inspection.
- [ ] Preserve safe rendering of source text, local security, provenance, and
      session isolation unless separately reconsidered by the maintainer.
- [ ] Write a bounded PRD and issues with independent acceptance criteria before
      replacing the UI or selecting new dependencies.

## Dependencies and scope

UI shaping can proceed alongside RAG evaluation. Implementation coordinates with
the chosen original-question interaction and coverage disclosure contracts.
Changing retrieval scores, adding another answering agent, and collecting new
annotations are outside this item. Browser verification requires explicit
maintainer authorization under the repo instructions.
