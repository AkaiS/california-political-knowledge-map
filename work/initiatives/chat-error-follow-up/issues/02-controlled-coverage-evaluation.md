# Specify a controlled evaluation of coverage and evidence support

Labels: enhancement, needs-triage
Parent: [Chat Session error follow-up](../MAP.md)

## Deliverable

A reviewed case matrix and bounded evaluation specification, followed by an
implementation brief. Use controlled evidence packages to evaluate the existing
Chat Agent's interpretation independently of passage retrieval quality.

## Current behavior and evidence

The chat evaluation task collects preparation, retrieval, and answer traces but
has no settled answer-quality evaluator. Final guidance already receives the
question, assessment, selected sources, collection coverage, branch statuses,
failure disclosures, and context omissions. This handoff exists; a new answering
or sufficiency agent is not required to measure it.

Reviewed patterns include false absence classification, reported perspectives
mistaken for motive inference, premature missing-reporting claims, partial
coverage causing a full decline, recoverable task drift, and decision/explanation
mismatch. The causal explanation for individual outputs remains provisional.

## Expected distinctions to review

| Controlled condition | Expected assessment or disclosure |
| --- | --- |
| Evidence supports the request | Present supported reporting and selected sources. |
| Evidence supports only a requested portion | Preserve that task portion and name what remains unsupported. |
| Selected evidence is irrelevant | Avoid claiming support or substituting a related topic. |
| Searches succeed with no useful evidence | Say supporting evidence was not retrieved, without proving absence. |
| A retrieval branch fails | Identify the search limitation separately from an empty successful search. |
| A required collection or capability is known unavailable | State that verified limit; Deferred may be justified. |
| Sources report different attributed positions | Present the perspectives without inferring motives or adjudicating truth. |
| The question genuinely requires unsupported motive inference | Preserve a legitimate policy decline. |
| Selection omits evidence under context limits | Distinguish the received context from exhaustive corpus coverage. |

Pre-search eligibility and post-search evidence support are separate judgments.
Avoid treating every unsupported answer as Deferred. Broad requests are not
automatically ambiguous; unresolved referents can be controls without designing
a clarification workflow in this issue.

## Acceptance criteria for the specification

- [ ] Each case supplies a question, fixed as-of context, verified collection
      metadata, branch outcomes, selected evidence, and provenance.
- [ ] Controlled cases can reach guidance directly without live retrieval and
      without being blocked by the current preparation classifier.
- [ ] Separate preparation controls expose false declines on factual and
      attributed-perspective requests, alongside legitimate policy declines.
- [ ] Reviewers can label supported portions, unsupported portions, known
      capability limits, and failed-search disclosures independently.
- [ ] Include at least one case for each condition above, plus contrasting
      controls for the known classification failures.
- [ ] Human-reviewed labels are recorded as Gold; unresolved labels remain
      explicitly pending and model labels remain Silver.
- [ ] Define training and held-out use before tuning; retained reviewed discovery
      examples do not masquerade as independent validation.
- [ ] Use binary checks tied to these errors and deterministic contract checks
      where possible. Any subjective judge needs calibration before trust.
- [ ] Record a baseline by failure type; select quality floors only after that
      baseline, without inventing a universal correctness score.
- [ ] The implementation brief reuses the current Git-backed evaluation runtime.

## Dependencies and scope

Specification and labeling can start now. Runtime implementation follows review
of the expected distinctions. Date-context implementation is not a blocker for
authoring fixed-date cases. Coordinate question input with the original-question
baseline decision; do not make that production change a prerequisite for isolated
coverage measurement.

Retrieval ranking, UI redesign, a new evaluator framework, live corpus expansion,
and automatic release gates are outside this specification.
