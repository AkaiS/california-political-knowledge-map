## Problem and verification limits

Preparation sometimes declares particular reporting unavailable using only a
Coverage Description. Reviewed corpus references contradict some of those
claims. `ChatSession` assesses the proposed question before searching and passes
the assessment into final guidance; the final introduction can repeat a Deferred
explanation. The code path and reviewed symptom are established. Whether a
particular prompt line or input causes each failure is not established.

## Intended behavior

Use early collection metadata for verified capability limits and question policy.
Determine what retrieved evidence supports after searching, in the existing Chat
Agent. A partial answer preserves a supported part of the person's task rather
than substituting a related topic. Distinguish no useful evidence retrieved,
search failure, context omissions, and known unavailable collections.

An empty successful search does not alone establish missing collection coverage
or a real-world absence. Preserve the domain meaning of Deferred. Keep the
existing deterministic Evidence Assembler responsible for grouping and limiting
evidence; it does not become an autonomous answering component.

## Shaping steps and completion criteria

- [ ] Obtain reviewed expectations and a baseline from the controlled evaluation.
- [ ] Replay representative errors while varying coverage input or instruction,
      holding question, evidence, and deployment constant where possible.
- [ ] Record whether prompt changes suffice or an assessment/handoff contract
      change is needed. Create new immutable prompt versions for trials.
- [ ] Decide which verified capability limits can stop preparation and which
      merely inform the eventual answer. Record policy eligibility separately.
- [ ] Decide whether the approved full request reaches retrieval and receives a
      partial answer, or a supported subrequest needs fresh explicit approval.
      A recoverable description is not itself an executable approved question.
- [ ] Specify how status and explanation stay consistent without inferring
      reliable semantics from free prose or brittle keyword matching.
- [ ] Write a bounded implementation brief and update affected domain/decision
      documentation if the accepted behavior changes.
- [ ] Evaluate the changed behavior on held-out cases and check that known failed
      branches and source validation remain correctly disclosed.

## Open decisions

The final disclosure shape, the scope of early capability gating, and the meaning
of approval during partial recovery require review. In current preparation the
recoverable portion is attached to approval, while the pending retrieval question
remains the rewritten full question. Do not assume this implements execution of
the recoverable portion.

## Boundaries

retrieval-ranking change, or mandatory pre-search clarification is specified.
