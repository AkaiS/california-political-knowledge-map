## Current attention

### Cloud in a Bottle portfolio deployment

The maintainer selected Imbue's $20 Large space and an initial OpenRouter budget
capped at $5/month. The [deployment plan](projects/cloud-in-a-bottle-deployment/PRD.md)
proposes one container for the web app, Neo4j and CPU embeddings, with persistent
corpus and Source Guide data, visitor isolation, off-server recovery and staged
publication. The [implementation record](projects/cloud-in-a-bottle-deployment/IMPLEMENTATION.md)
captures the running AMD64 app, visitor controls, prepared corpus and passing
local checks. The app is public on paid Gemma 4 26B through exclusive DeepInfra,
using the dedicated $5/month OpenRouter key. The assessment integration fix
passed local regression tests and the final anonymous HTTPS guide check.
Backup configuration and off-server restoration are deferred at the maintainer's
request. GitHub OAuth is unnecessary for the now-public repository.

### Consistent evaluation execution

The `run-evaluation` skill routes contextual evaluation requests to the maintained
[execution and reporting script](../scripts/run_evaluation.py). Ordinary RAG runs
select the complete 25-case retrieval Silver Set; mini sets require an explicit
request. [ADR 0024](../docs/adr/0024-evaluations-preserve-the-selected-population-and-progress.md)
supersedes ADR 0017 and preserves failed and incomplete attempts through atomic
progress snapshots. The [retrieval guide](../docs/evaluation/retrieval.md) documents
the commands; the RAG reviewer permits execution notes on failed and unresolved
cases alongside evidence-backed relevance and faithfulness judgments.

## Information model

| Level | Purpose | Location |
| --- | --- | --- |
| Roadmap | Product outcomes and strategic sequence | `roadmap.md` |
| Initiative | A large uncertain area that needs investigation | `initiatives/<slug>/` |
| Project | A bounded deliverable described by a PRD | `projects/<slug>/` |
| Issue | An independently completable change or investigation | A project's `issues/` directory or `issues/` |
| Code review | Whether a project's build matched its PRD | `projects/<slug>/code-review/` |
| Inbox | Unshaped ideas, defects, questions, and observations | `inbox.md` |
| Archive | Superseded plans and immutable imported source notes | `archive/` |

Supporting knowledge remains outside this hierarchy:

- [`CONTEXT.md`](../CONTEXT.md) defines the domain language.
- [`docs/adr/`](../docs/adr/) records durable architectural decisions.
- `.scratch/` contains disposable runtime output, not project plans.

## Label convention

`Labels:` is the only state header. Do not add a separate `Status:` field.

Each work item should have exactly one triage-state label:

- `needs-triage`
- `needs-info`
- `ready-for-agent`
- `ready-for-human`
- `completed`
- `wontfix`

Additional descriptive labels may share the same comma-separated line. For
example:

```text
Labels: wayfinder:research, ready-for-human
```

The triage-state label says what should happen next. Other labels describe the
kind of work.

## Archive

- `archive/imports/` contains verbatim snapshots of the two Obsidian notes used
  to seed this structure.
- `archive/legacy-plans/` contains completed or superseded standalone plans
  formerly located at the repository root.
